# 持久设备与账号播放实验

本轮针对 [#118](https://github.com/N3urda/hongguoTV/issues/118) 和 [#119](https://github.com/N3urda/hongguoTV/issues/119) 补齐设备与账号上下文。它提供可验证的账号取流路径，不代表已经复现或修复“启动官方 App 后恢复播放”的服务端原因。

2026-11-25 补充：登录后仍空流的固定设备对照定位到 V5 签名缺少 f16。仅补这一字段后，游客生产路径的三个样本恢复模型，且一个加密媒体样本成功解码首帧。该字段不是账号 Token，重新登录不能替代它。详见 [实验与边界](../research/2026-11-25-empty-playback-f16.md)；实体电视的账号播放仍需验收。

## 统一签名与会话生命周期

`AppRequestSigner` 统一接收最终 URL、请求方法、实际压缩正文、完整请求头和设备/登录代际。主模型、补充模型、实验短信登录和 App 来源的云端接口共用同一签名实例。账号 Token/Cookie 在签名前加入，HTTP 正文与签名输入使用同一份字节；签名器只允许返回规定的三个安全头，不能改变目标、正文或账号凭据。

同一入口接收 API 响应头，让原生 SDK 维护已支持的动态策略；观察失败时关闭响应，不把未完成验证的模型或会话更新交给上层。CDN/VOD 响应不进入此管道。

默认构建使用纯 Kotlin V5，包含 f16 修复，兼容原有 Android 5 与 ARM32 路径。通过 `-PnativeSigningSdkDir=...` 显式启用本机 ARM64 SDK；该构建校验 SDK 和配置哈希、使用独立构建目录，不在运行时下载二进制。SDK 输入由本机提供，原生库、完整配置和设备/账号数据不提交到 Git。具体准备和验证方式见 [原生签名构建](native-signing.md)。

原生实现将初始化、首次安装事件、fetchedDid 登记通知、设备绑定/更新、登录事件、签名放在同一把锁内。fetchedDid 使用本机已注册的 DID；固定设备对照确认，补上该入口后原生 SDK 自行生成 f16 并取得正常模型。登录成功后创建的随机代际随账号加密保存，Token/Cookie 刷新保持该代际，避免每次响应刷新都重新报告登录。已保存的旧 App 登录也有稳定的兼容代际。事件调用成功只表示本机 SDK 返回，不代表服务端已经授信；不猜测 `setSessionID` 或额外 HTTP 激活接口。

原生初始化、未知回调或签名失败会明确报错，不自动换设备或切回 Kotlin。账号范围和模型范围继续隔离，VOD/CDN 请求不接入账号和签名拦截器。

设置中的账号播放状态区分“账号已登录，播放尚未验证”“已取得播放信息”和“本次账号会话已成功播放”。只有当前代际已取得对应模型、正式播放器渲染首帧后才标记成功，重启或切换账号重新验证；预加载成功不能当作实际播放成功。错误详情仅记录模式、签名后端、Token/Cookie 是否携带和验证阶段，不含具体值。

## 使用

- 默认保持游客取流，但设备注册身份现在会在本机持久保存，重启不会重新生成。
- 在 **设置 → 账户 → 账号播放（实验）** 开启实验，然后通过账户页的短信入口重新登录。
- 实验登录使用与播放器相同的注册设备，保存服务端返回的 App Token 和带作用域的 Cookie。账号播放使用该次登录的完整设备上下文。
- 旧登录态、网页登录及手机控制台扫码登录不会自动变成 App 播放会话。开启实验但使用这些登录态时，会提示重新登录；不会静默混入新的匿名设备。
- 没有登录账号时仍可游客播放。关闭实验可恢复游客取流，保留账户收藏、历史和登录状态。
- 如果服务器要求重新登录，播放器停止自动重试并提供“账户管理”入口。连续空响应后会暂停请求 30 秒，手动重试和切换集数不能绕过这段本地等待。

该开关默认关闭。真实账号在设备上的成功取流、首帧、切集及会话长期续期仍需验收。

## 实现

### 设备上下文

`PlaybackDeviceSession` 在注册前持久保存 cdid、openudid、clientudid 和安装时间；注册成功后保存 did、iid、device_token、klink_egdi 及注册 Cookie。网络失败继续使用同一份种子，已有数据损坏时报告错误，不自动轮换身份。

应用从 Android Build 和显示信息取得型号、品牌、厂商、系统版本、ABI、屏幕尺寸和 DPI。注册请求、现行模型 query 与 V5 签名共用一致的设备信息和协议版本。V5 签名不再把品牌固定为 HONOR，User-Agent 也与该上下文一致。

数据存放于独立的应用私有 `playback_device` 分区，不与历史 aid=1967 的 `player-device` 混用，不包含在片单导出中。应用本身禁用 Android 自动备份。

### 账号上下文

`AccountCredentials` 增加登录来源、应用范围、Token 和 Cookie 元数据，兼容旧序列化格式；仍通过现有 Android Keystore 加密存储，不在诊断中输出值。

实验短信登录使用持久设备；原有短信兼容路径在开关关闭时保留。现有网页二维码登录仍用于账户功能，标记为 Web 来源。

App 来源的账号资料校验及云端数据请求也沿用该设备版本和会话，不再强制覆盖为旧版本参数。账号接口返回的新会话可同步给播放器；同账号的凭据更新不会清空正在使用的播放上下文，较旧响应不能覆盖更新结果。V5 的无正文请求使用空字节的 MD5 参与签名，保留独立的设备签名信息。

`PlaybackContextProvider` 为一轮取流提供设备与账号快照。主模型、video-tab 补充请求和同域的替代模型请求使用同一上下文。只向允许的 HTTPS 模型域名和路径加入账号头；不跟随模型重定向，不将账号凭据带到 VOD 协商或媒体 CDN。

模型响应返回新 Token / Cookie 时，更新当前会话并串行写入加密存储；HTTP 401 清除该播放会话的凭据并提示重新登录。账号切换、退出或实验模式变化会取消原有请求，作废预取和最近播放源；旧响应不能恢复旧账号或向新会话交付模型。实验关闭时，账户恢复不会中断仍在使用的游客取流。

### 请求数量

首页与全屏播放器共用 provider。同一集的重叠模型请求合并执行，连续两轮空响应后跨集数暂停 30 秒；明确的服务退避立即暂停。设备注册也共享失败退避，后台预取不能创建新设备。页面自己的恢复按钮不能清除此限制。

## 已有验证与未覆盖范围

2026-11-25 最终统一管道验证：440 项核心测试、361 项 Android 6+ 测试和 434 项 Android 5 测试通过，均无失败或跳过；两种兼容构建均完成 lint 与 debug 打包。通过生产 `ContentRepository` / `PlaybackContextProvider` 路径，用同一持久游客身份取得 5 档模型；一个加密媒体样本读取 4 MiB，HTTP 206，FFmpeg 解码首帧成功。原生 SDK 包另在隔离 ARM64 模拟器通过三个样本的正式播放器、拖动、切集、暂停恢复和同设备进程重启验证，详见 [原生签名构建](native-signing.md)。三种最终 APK 均通过签名校验。这些结果尚不是用户电视和账号的验收。

自动化覆盖设备种子及注册结果跨实例恢复、加密注册请求与模型字段一致性、注册失败退避、登录来源迁移、实验短信会话、Token 更新、Cookie 作用域/删除、401、跨账号取消、模型重定向隔离、VOD 凭据隔离、并发请求合并及全局退避。Android 测试验证首页和播放器使用同一个上下文。

本轮没有猜测实现官方 SDK 的主动 Token 刷新、TokenGuard 或设备证明协议，也没有把 `app_alert_check` 的出现解释为已验证的修复。`device_token` 保留供后续协议验证，未擅自作为未知请求头发送。当前实现处理响应中的会话更新，明确过期时要求正常重新登录。

账号自动化使用本地响应夹具，不发送真实验证码，不代表平台已经接受了实验登录或账号播放。启用实验后，如果平台拒绝短信流程，应保留返回的安全错误类别并停止反复尝试；可关闭实验继续原有账户功能。

## 实机验收

1. 在能正常播放官方 App 正片的实体设备上，确认新版游客身份重启前后稳定。
2. 开启实验，通过本人的账号完成一次登录。确认请求使用同一设备上下文，且平台确实下发会话；不导出凭据值。
3. 验证模型非空、实际首帧、切集、首页进入全集、重启恢复、响应 Token 更新和退出账号。
4. 同一剧集对照游客与账号模式，记录路由、HTTP 状态、响应长度及模式，不把 HTTP 200 等同于可播放。
5. 另行分阶段复现仅安装、首次初始化、游客播放、登录和登录后播放对 #119 的影响。只有这组证据才能支持根因判断及默认开启账号模式。

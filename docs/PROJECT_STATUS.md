## 已有研究结论

1. 找到了直接请求红果/番茄平台域名的公开实现，可以作为接口研究起点。
2. `drpys` 的“红果果[短]”源包含搜索、详情和播放代理流程，适合优先检查完整调用链。
3. `zhenyong97/hongguo-downloader` 的接口模块集中实现分集列表和视频信息请求，适合交叉核对参数及数据结构。
4. 一些同名项目仅调用第三方服务、依赖另外提供的组件，或面向 Apple TV，不能直接当作 Android TV 成品。
5. 源码中存在固定设备参数、请求签名和加密视频处理；这些依赖尚未实测。

证据与源码链接见[开源项目调研](research/2026-09-21-hongguo-open-source.md)。上述结论来自代码审阅，不是实际运行结果。

## 建议的工作顺序

### 第一阶段：接口与播放验证

- 选定少量测试剧集，确认搜索结果能映射到剧集 ID。
- 获取完整分集列表并核对顺序、标题和集数。
- 验证单集实际播放与下一集切换。
- 检查地址过期后的重新获取、错误响应及请求所需的状态。
- 记录可复现的步骤和结果，明确成功、失败与未覆盖的部分。

阶段验收以实际播放为准；仅获取 JSON 或视频 URL 不代表通过。

### 第二阶段：确定架构

- 根据验证结果决定接口层位于 Android 客户端还是独立服务。
- 确定目标 Android 版本、设备性能范围和首版功能。
- 评估 Kotlin、Compose for TV、Media3 的具体适配方案。

### 第三阶段：实现与电视端验收

- 完成浏览/搜索、详情/选集、播放三个主要路径。
- 加入收藏、续播、自动下一集及竖屏比例显示。
- 在模拟器和目标电视上验证遥控器导航、返回、重启续播和播放异常恢复。

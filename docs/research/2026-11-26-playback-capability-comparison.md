# 取流接口与能力参数实网对照

基线为主分支 `2d7403c`（0.16.16）。测试日期：2026-11-26，使用同一台新注册的游客设备、同一网络、同一集及当前 Kotlin V5 签名；不使用账号 Cookie。每轮仅注册一次设备，不通过高频轮换身份重试。

## 结论与范围

本轮采用最小改动：现行 App 预加载请求的 `device_level` 从 2 调整为 4，保留 `video_platform=1024`、74532 profile、`reading.snssdk.com`、V5 签名和已有回退。旧协议的 level 1 不变。

截图方案的单集接口确实可以返回模型，但本轮收益来自能力等级：只改 level，在原预加载接口也能获得相同兼容档位。因此没有同时迁移域名、签名、版本或增加设备凭据。

这是本次样本、网络和时间窗口的结果，不表示所有剧集都会返回 HEVC，也不保证上游长期接受这些参数。保留 bytevc2 过滤、模型提供的 VOD 编码协商及有界空响应恢复。

## 请求对照

三个固定问题分集：`7704857946630409240`、`7709114791150767128`、`7709197486451084312`。单集请求使用 `/novel/player/video_model/v1/`，顶层 `video_id`、`content_type=1004`；预加载请求保持 `mixed_video_id_map` 和 `dr_scene=preload`。每次按实际发送的压缩字节重新签名，签名后的参数不再改写。

| 请求形态 | 第一个样本的兼容档位 | 另外两个样本 | 结论 |
|---|---:|---:|---|
| 预加载，level 2 / platform 1024 | 0，需要 VOD 协商 | 各 5 档 HEVC | 基线可播放，但第一个样本多一次协商 |
| 单集，level 2 / platform 1024 | 0，需要 VOD 协商 | — | 仅换接口未改变第一个样本的编码供给 |
| 单集，level 2 / platform 3 | 0，需要 VOD 协商 | 各 5 档 HEVC | 仅换 platform 未改善第一个样本 |
| 单集，level 4 / platform 1024 | 5 档 HEVC | 各 5 档 HEVC | 保持原签名与版本即有效 |
| 单集，level 4 / platform 3 | 5 档 HEVC | 各 5 档 HEVC | 未见相对上一行的额外收益 |
| 预加载，level 2 / platform 3 | 业务码 100001 | 同为 100001 | 不兼容，不能直接移植该参数 |
| 预加载，level 4 / platform 1024 | 5 档 HEVC | 各 5 档 HEVC | 最小改动即可取得相同结果 |

单集接口在 reading、sinfonlinea、sinfonlineb 域名均取得模型；有无注册 Cookie、gzip 与未压缩正文在第一个样本均能取得模型，不能据此宣称这些改动是必要条件。不同域名出现过约 3 秒的首次请求延迟，不据此作普遍性能排名。

## 验收

基线 API 36 Android TV 模拟器：三个问题分集、下一集、拖动、暂停恢复均通过，实际解码 1920×1080 并持续推进。这次优化不是把该基线描述为完全无法播放，而是减少已观测到的额外协商。

完整取流进一步按 level 2 → 4 → 4 → 2 的顺序在同一注册设备上对照，每次重新获取模型。三个样本共 12 次全部成功，并各自读取 65,536 字节的实际 CDN 视频数据：

- 第一个样本：level 2 两次均为 1 次模型请求 + 1 次 VOD 协商；level 4 两次均为 1 次模型请求、0 次 VOD 协商。均获得 5 档兼容资源，选取 720P 读取成功。
- 另外两个样本：两种等级均为 1 次模型请求、0 次 VOD 协商、5 档兼容资源，720P 读取成功。
- 第一个样本的模型总耗时：level 2 为 2,589 / 263 ms；level 4 为 133 / 136 ms。这里只证明当前样本减少一次协商，不据此宣称普遍加速倍数或长期成功率。

候选 API 23 和 API 36 模拟器均已通过与基线相同的三个分集、下一集、拖动与暂停恢复验收，实际解码 1920×1080 并推进。发布还需完成 Android 5 兼容验收、完整回归及正式包检查，执行结果记录在发布 PR 中。本轮没有实体电视验收。

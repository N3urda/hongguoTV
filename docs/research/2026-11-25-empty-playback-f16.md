# 登录后仍空流：V5 f16 缺失的固定设备对照

日期：2026-11-25。代码基线：`dd1b82f`，分支 `codex/account-playback-context`。

## 结论与边界

用户已开启账号播放实验并用短信重新登录，仍然空流。对当前代码的独立游客实验发现：V5 Medusa 信封缺少 f16；补入 `A` 前缀加 24 字符进程 nonce 后，同一设备、同一请求恢复非空模型。该字段不是账号 Token，也不是注册响应的 `device_token`。

最小修复只添加 f16，保留 f5、flags、环境字段、f15、f21=312、请求头、接口和设备身份。没有加入自动换设备、强制重新登录或猜测的激活流程。

验证在本机 JVM 进行。未使用用户账号，未连接用户电视；不能把游客实验说成账号模式的实机验收，也不能据此解释 #119 中官方 App 启动后所有第三方恢复的全部原因。

## 实验控制

只注册一次游客身份并写入本地忽略目录，所有实验继续加载同一份设备数据；不轮换 did/iid/cdid，不使用 Cookie 或账号 Token。注册响应含 `klink_egdi`，未提供 `device_token`。所有请求使用同一 preload 接口、同一版本、同一剧集、相同压缩正文；时间戳和请求签名按每次请求正常生成。

候选签名器仅存在于 `outputs/issue119-followup/src/`。记录只保存阶段、状态、字节数、业务码和模型数量，不保存凭据、设备 ID、签名 URL 或完整模型。

### 第三轮：拆分 f5、f16 和格式

| 条件 | HTTP / 字节 | 模型 |
| --- | --- | --- |
| 原实现 | 200 / 0 | 无 |
| 新增 f16，使用原 24 字符 nonce，无 A 前缀 | 200 / 0 | 无 |

这支持当前环境下最小修复的因果判断。没有证明 f16 的所有内容语义，也没有证明其他环境永远不需要其他字段。

## 生产路径与媒体验证

将最小修复应用到生产 `Signer` 后，通过 `ContentRepository.streamLadderWithCompatibility` 和持久 `PlaybackContextProvider` 验证三个公开样本，各返回 5 档，最高 1080P。取其中一个 720P 媒体的前 4 MiB，HTTP 206；使用模型提供的内容密钥，FFmpeg 成功解码一帧，退出码 0。媒体片段与含临时地址/密钥的中间文件已删除。

脱敏记录保存在忽略目录：`results.json`、`ablation-results.json`、`token-results.json`、`production-results.json`、`media-result.json`。这是模型及媒体链路验证，不是电视上的首帧、遥控切集或长时间播放验收。

## 后续维护方式

1. 保留持久设备与账号上下文、Cookie 作用域和退避机制；账号登录与播放是否可用分别判断。
2. 将 f16 完整签名向量纳入回归，同时保留独立 SDK 摘要和 carrier 向量。新增完整向量来自隔离候选，是本地回归向量，不能冒称独立 SDK oracle。
3. 私有协议更新时先固定设备做旧/新交替对照，再逐项拆分；不要同时混改登录、设备、接口和签名而失去因果证据。
4. 发布验收同时要求模型非空与实际解码，并补上实体电视游客/账号两种模式、重启、切集和长时间播放。一次成功不等于接口永久稳定。

该实验没有发布正式版本或关闭 issue；后续实现与构建方式见 [账号播放](../features/account-playback.md)。
